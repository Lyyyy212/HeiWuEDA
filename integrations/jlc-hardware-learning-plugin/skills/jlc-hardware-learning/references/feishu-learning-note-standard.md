# 飞书硬件学习笔记标准（JLC-FN-1.3）

本标准适用于 JLC Hardware Learning 同步、创建、导出或修订飞书硬件学习笔记。任何未通过写后回读与预览验收的操作都不得报告为“已完成”。

## 1. 文档结构

- 每个项目只维护一个项目主页 Docx；`00..99` 分类是主页内部标题，不创建空分类文档。
- 项目主页首先固定嵌入一张“工程原理图总画板”；该画板集中导入当前工程的全部真实原理图页，作为项目级总入口。
- 仅真实原理图图页创建独立子 Docx。
- 每个真实原理图页长期复用一个 `docToken` 和一张图页学习画板 `whiteboardToken`；同一原理图页上的所有模块共用这张画板。
- 不按模块单独创建画板，也不再为每个图页额外创建模块索引画板；模块导图直接放在所属原理图页的学习画板上。
- 图页正文固定包含：图页身份与证据、图页学习画板、学习框模块索引表、问答记录、检查/实验记录。
- 旧笔记已有的模块索引画板只作为 `legacyModuleIndexWhiteboardToken` 保留，不删除、不替换，也不作为新模板的必需资源。

## 2. 读者可见内容与内部绑定

- `projectId`、`projectUuid`、`canvasPageId`、`schematicPageUuid`、`docToken`、工程总画板 token、图页学习画板 token，以及图片 shape/asset ID，只用于注册表、同步、校验和写后回读。
- 上述绑定标识不得出现在读者可见的标题、正文、提示框、图片标题、图片说明、表格或思维导图中。
- 项目与图页身份区只显示可读的项目名称、图页名称和必要的来源版本；图片和画板只显示内容名称，不显示绑定 ID。
- 飞书链接所需的 `doc-id`、画板节点 token 等允许保留在不可见的节点属性中，但不得转成可见文字。
- 模板生成、旧笔记迁移和后续同步均必须通过“读者可见文本不含绑定标识”的自动检查；内部标识仍须完整保留，不能因隐藏显示而解除绑定。

## 3. 工程总画板与图页学习画板合同

### 工程原理图总画板

- 每个工程固定一张，绑定在项目主页，不随模块数量增加。
- 必须覆盖该工程当前登记的全部真实原理图页；每张图页只导入一次，并保留可读图页名称与内部图页身份校验。
- 只负责工程级全局浏览和进入各图页学习记录，不承担学习框问答归档。
- 新增、删除或更换工程原理图页后，必须重新核对总画板的图页集合；不得用标题猜测图页身份。

### 图页学习画板

- 每个真实原理图页最多一张，画板必须且只能导入该图页的原理图证据。
- 学习框按已验证的 `schematicPageUuid` 归类：学习框位于哪张原理图，就把该框、序号、模块名称、一句话总结和相关问答归入哪张图页画板与图页 Docx。
- 同一原理图页上的多个模块共用同一张图页学习画板；禁止按模块重复创建画板。
- 一个学习框不得跨图页复制归档；图页身份缺失或证据不一致时停止同步，不按名称或编号猜测。
- 图页学习画板必须同时包含：该页原理图证据、该页全部学习框与固定序号、该页模块索引思维导图，以及与学习框同色的模块标签和总结分支。
- 只存在思维导图、没有对应原理图和学习框的图页学习画板不合格。

### 导图文案

导图固定为三层：

```text
<图页名称> 模块索引
└─ 框N <真实模块名称>
   └─ <对该模块的一句话总结>
```

- 末级节点只写对模块原理、功能或作用的一句话总结。
- 不得写成“学习状态｜核心功能”，也不得单独使用“待学习”“学习中”“已总结”“需复查”等进度占位词。
- 学习状态保留在飞书正文的学习框索引表中，不进入导图总结节点。
- 总结必须非空、简洁且能单独说明该模块；详细原理和问答继续放在正文中。

## 4. 学习框与序号

| 项目 | 固定规则 |
|---|---|
| 学习框 | 圆角矩形；透明填充；边框透明度 50%；`narrow` 边框 |
| 序号 | 圆角矩形；宽 `29.2544002532959`；高 `28.414939880371094`；字号 12 |
| 序号位置 | `x = frame.x - 8`，`y = frame.y - 8`，压在框左上角 |
| 序号样式 | 边框透明度 50%；填充透明度 50%；`narrow` 边框；颜色跟随学习框 |
| 编号语义 | 图页内正整数、单调递增、删除后不复用；序号、模块标签和正文索引保持一致 |

原理图从源画板映射到目标画板时，仅学习框几何跟随图片变换：

```text
scaleX = targetImage.width / sourceImage.width
scaleY = targetImage.height / sourceImage.height
frame.x = targetImage.x + (sourceFrame.x - sourceImage.x) * scaleX
frame.y = targetImage.y + (sourceFrame.y - sourceImage.y) * scaleY
frame.width  = sourceFrame.width  * scaleX
frame.height = sourceFrame.height * scaleY
```

序号的宽、高、字号和 `-8/-8` 偏移保持固定，严禁乘以 `scaleX` 或 `scaleY`。

## 5. 颜色

- 颜色无固定语义，只用于区分模块；从柔和候选色中按图页稳定分配。
- 同页在候选色用完前不重复；重新导出时保持原分配，不重新随机。
- 同一图页画板内，学习框、序号、模块索引标签和对应说明分支使用同一模块颜色。
- 模块索引标签的边框/填充透明度为 50%，说明分支边框透明度为 50%，均使用 `narrow` 边框。

## 6. 标准执行流程

1. fresh-read 项目主页、工程总画板、全部图页 Docx 与图页学习画板；绑定项目、原理图页和文档身份。
2. 导出工程总画板及所有目标图页画板的 raw JSON 与 preview 图片到时间戳证据目录，记录节点数和 SHA-256。
3. 先核对工程总画板是否覆盖全部原理图页，再按 `schematicPageUuid` 把每个学习框分配到唯一图页画板；身份缺失或重复时停止。
4. 生成精确变更计划：目标 token、图页集合、学习框归属、节点增删数量、字段差异、预期编号、颜色和几何。
5. 新增节点优先 append；修改已有节点属性只能 raw overwrite 时，先保存完整备份并取得用户对精确目标的明确确认。
6. 写入前执行 dry-run；同一次逻辑写入固定复用一个幂等 token。
7. 写入后 fresh-export raw 与 preview；逐项核对总画板图页集合、图页画板原理图身份、学习框归属、节点数、图片 token、思维导图关系、框/序号几何、颜色、透明度和边框。
8. 只有 raw 比对和预览目检都通过，才更新本地注册表并报告完成；不一致时报告差异，不得声称已修复。

## 7. 强制验收

- 项目主页只有一张工程原理图总画板，且覆盖工程全部原理图页。
- 每个真实原理图页最多一张图页学习画板；没有按模块重复创建画板。
- 每个学习框只归入其实际所在原理图页的画板和 Docx，同页多个模块共享该画板。
- 现有 Docx、工程总画板和图页学习画板 token 未被替换；遗留模块索引画板未被擅自删除。
- 读者可见内容不含项目、图页、画板或图片绑定 ID；这些标识只存在于内部注册表和不可见节点属性中。
- 每张图页学习画板含该页原理图、学习框、序号和模块导图，不只是文字索引。
- 图页画板、正文索引的编号集合、模块对应关系和颜色一致。
- 每个模块索引末级节点是一句话模块总结，不是学习状态或占位词。
- 所有序号均为固定 `29.2544 × 28.41494`，且位于对应框 `-8/-8` 处。
- 原理图缩放没有改变序号尺寸。
- 框透明填充；框线和序号透明度 50%；边框为 `narrow`。
- 思维导图关系和原理图证据节点保持不变。
- 写后 raw 与 preview 均已重新导出并通过检查。

校验原始画板导出时运行：

```powershell
node ./skills/jlc-hardware-learning/scripts/validate-feishu-learning-board.mjs `
  --raw ./project-overview.json --role project-overview --expected-images 3

node ./skills/jlc-hardware-learning/scripts/validate-feishu-learning-board.mjs `
  --raw ./schematic-page.json --role schematic-page --expected 4,5,7
```
