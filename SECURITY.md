# Security policy

## Supported version

Security fixes target the latest commit on `main` until versioned releases are
published.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature when it is enabled for the
repository. Do not post access tokens, private EasyEDA project data, project or
page UUIDs, exported schematics, BOMs, netlists, screenshots, Bridge logs or
local filesystem paths in a public issue.

Include the affected version, a minimal sanitized reproduction and the expected
security boundary. Reports involving persistent EasyEDA writes should state
whether explicit save authorization was present; do not test against projects
you do not own or control.
